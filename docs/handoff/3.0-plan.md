# Trainer's Workshop 3.0 – Challenge mode plan

Approved on 2026-11-26. Part 1 was research only; this file holds what it found and the decisions taken.
`docs/challenge-code.md` (copied from PokéRoll v1.4.0, commit 0e7cdd8) is the contract for the codes and wins over this file.

## Target

- COBBLEVERSE 1.8.0: Cobblemon 1.8.4, rctmod 0.19.2-beta, rctapi 0.16.2-beta (checked in the instance's `mods/`).
- Trainer data: `COBBLEVERSE-RCT-DP-v20`. The owner compared it with v21 (COBBLEVERSE 1.8.0): gyms, Elite Four and champions are the same; v21 only adds `prof_prof_oak_01ff`.

## Rules (decided)

**Codes**
- New codes only use `rule:"evo"`. Older codes with `rule:"exact"` / `mode:"minigame"` must still work.
- A slot is identified by `dex` + `special`, never by `name`.
- `special: null` + `evo`: every form of that species (regional forms too), and every later evolution of those forms.
  Example: Meowth allows Meowth, Alolan Meowth, Galarian Meowth, Persian, Alolan Persian and Perrserker.
- `special: "kazeran-…"` + `evo`: that Kazeran form and its later evolutions.
- `exact` (older codes): only that species, base form.

**Who counts**
- A Pokémon is valid only if the player got it (caught, hatched, received) after the challenge started, and the player never owned that Pokémon (by UUID) before.
- Party ↔ team is one-to-one: each team slot is filled by at most one party Pokémon, and each party Pokémon fills one slot.
  Two Pikachu are only valid if the team has two Pikachu slots.
- A slot changed by a reroll still only needs a Pokémon obtained after the original start (the start time is not reset by "Reroll 1").

**Which battles**
- Only the Gym Leaders, Elite Four and Champions of Kanto, Johto, Hoenn and Sinnoh are challenge battles (list below, in the config).
- Radical Red, BDSP and Unbound leaders / Elite Four / champions are in the config too, but off by default.
- Only challenge battles check the party (Blocked screen) and show the Defeat screen. Other trainers are never checked.

**Results**
- Winning any challenge battle completes the challenge. Each battle is one challenge: after a win the player rolls a new team.
- Loss → Defeat screen:
  - **Keep going**: nothing changes.
  - **Reroll 1**: the mod makes a TWR1 code with `allow: 1`. The player rerolls 1 slot on PokéRoll and pastes the new TW1 code.
  - **Reroll all 6**: no TWR1 code. The current team is cleared; the player uses Start over on PokéRoll and pastes a new TW1 code. That is a new challenge with a new start time.
- Abandon: no penalty. Rewards already given are never taken back.

**Rewards**
- Each team slot with `shiny: true`: 128 EV feathers (2 × 64) of a stat the player picks, per slot.
  Each (code id, slot) pays once. Importing the same code again pays nothing; a reroll result only pays for newly rerolled shiny slots.
- Gym win: no reward.
- All 4 Elite Four of the same region beaten: 1 Master Ball, once per region.
- Champion beaten: 1 Shiny Berry, once per champion.
- A rematch still completes the challenge, but the mod's rewards are not given again.

**Rematches**
- Every RCT trainer (gym, Elite Four, champion and normal trainers) can be battled again any number of times, even after a win, with or without challenge mode.
- Config `unlimitedRematches` (default `true`) turns this off.

## Research results

### UI style

- Cobblemon Interface v1.6.0 restyles vanilla Minecraft widgets (buttons, text fields, scroll bars, containers). For Cobblemon it only overrides `starterselection/starterselection_*.png` (old names that 1.8.4 no longer uses), `campfirepot/*` and `jei/*`.
- Cobblemon Interface Modded v1.9.4 restyles other mods. For RCT it only overrides `rctmod/textures/gui/trainer_card.png`.
- Neither pack touches Cobblemon's `summary/*`, `pc/*`, `party/*`, `trade/*` or `dialogue/*`.
- So the new screens use the Summary style the editor already uses (GuiKit, CobbleButton, `summary/summary_base.png`, `summary_party_slot*.png`, `icon_shiny.png`, `dialogue/dialogue_box.png`, `common/back_button.png`), loaded by identifier at runtime.
- The code input is a vanilla `TextFieldWidget`, so it follows the pack's `widget/text_field` sprite automatically. Its max length must be raised (default 32; a TWR1 code is about 1,500 characters).
- No texture is copied from a resource pack or another mod. Missing icons are drawn by hand in the style of `tab_icon_*.png`.

### Hooks (evidence from javap)

- **Cancel a battle before it starts:** both start paths (`TrainerMob.method_5992` = interact, and `tryStartBattle`) call `TrainerMob.startBattleWith` → `RCTMod.makeBattle`. When `makeBattle` returns false, `startBattleWith` just returns (offset 36 → 146): no start dialog, no cooldown. Plan: a cancellable HEAD inject on `makeBattle` in the existing `RCTModMixin`.
- **Win / loss:** `ModServer.onBattleVictory` → `removeBattleFromInitiator` → `TrainerBattle.distributeRewards(boolean initiatorWon)`; with `true` RCT calls `addProgressDefeat` (offset 125). RCT removes the battle inside `BATTLE_VICTORY`, so the mod hooks `distributeRewards` (HEAD mixin, `remap=false`, `require=0`). A forfeit is a loss. A stopped battle or a server stop has no result.
- **UUID:**
  - Evolution changes the Pokémon in place: `Evolution.evolutionMethod` clones only for the "before" snapshot (offset 16), then `getResult().apply(pokemon)` (offset 27). Shedinja is a new Pokémon (`shed`, then `POKEMON_GAINED` at offset 555).
  - Trade moves the same object: `TradeManager.performTrade` removes and adds the same `Pokemon`.
  - `setUuid` is only called by codecs, `ReforgedConversion` and `SpawnPokemonPacket`.
  - PC in/out: inferred to keep the object (no UUID change found); to be checked in game.
  - Eggs (Cobbreeding 2.4.1, eggs are items): `PokemonEgg.hatchEgg` makes a new Pokémon with `PokemonProperties.create` (new UUID), then `PlayerPartyStore.add` and `HATCH_EGG_POST`.
- **Pokémon gained:** `CobblemonEvents.POKEMON_GAINED` fires every time a Pokémon's store changes (a lambda in `Pokemon.<init>`), including party ↔ PC moves. So it is not "new"; the UUID ledger decides.
- **UUID ledger:** per player, UUID → first seen (time). Fed by `POKEMON_GAINED` and by a party + PC sweep on login and at challenge start. Valid = first seen after the challenge start. Limit: Pokémon from before the mod was installed have no history; the first sweep marks them as already owned.
- **Items:** HP `cobblemon:health_feather`, Atk `cobblemon:muscle_feather`, Def `cobblemon:resist_feather`, SpA `cobblemon:genius_feather`, SpD `cobblemon:clever_feather`, Spe `cobblemon:swift_feather`; `cobblemon:master_ball`; `trainers_workshop:shiny_berry`.
- **Evolutions:** computed at runtime from `PokemonSpecies` (`FormData.getEvolutions()` → `getResult()`), so datapack forms are included. Kazeran adds a "Kazeran" form to the base species, and adds evolutions to Eevee through `species_additions`, so "Eevee evo" includes the Kazeran forms.

### Rematches (evidence)

- RCT 0.19.2-beta has no config or gamerule for this: `IServerConfig` has no such option and rctmod registers no gamerule.
- The limit is `TrainerMob.wasDefeatedBy(UUID)`: true when this trainer entity's defeat count by that player ≥ `maxTrainerDefeats` (1 for every gym / Elite Four / champion, 5 for the Hoenn champion). `wasVictoriousAgainst` does the same with `maxTrainerWins`.
- Used in:
  - `couldBattleAgainst` (can the battle start) → **lift here**;
  - `finishBattle` offset 320: after the limit is reached the trainer is marked `done` and leaves (`detachTicks`) → **lift here too**, or a gym leader walks away after one loss;
  - `updateTarget` (force battle on sight) and `replyTo` (dialog) → **left alone**, so a beaten trainer doesn't force a battle every time the player walks by.
- Plan: `@WrapOperation` on the `wasDefeatedBy` / `wasVictoriousAgainst` calls inside `couldBattleAgainst` and `finishBattle` (`remap=false`, `require=0`), returning false when `unlimitedRematches` is on.
- Effect on RCT progress:
  - Series progress / level cap (checked in bytecode): a win calls `TrainerPlayerData.addProgressDefeat(id)`. Its lambda only updates `PlayerState`, the current series and the save when `defeatedTrainerIds.add(id)` returns true (offset 13), and `PlayerState.addProgressDefeat` has the same guard (offset 10). The level cap is never stored: `TrainerPlayerData.getLevelCap` calls `LevelUtils.levelCap(player)`, which computes it from the current series and the set of defeated trainer IDs. So a rematch can't raise the level cap or move the series on.
  - Loot: badges and badge boxes in the COBBLEVERSE loot tables have `rctmod:defeat_count == 1`, so they are not given again. The random reward pool (for example Brock's TM) has no condition and drops on every win, so rematches can farm it. That is how RCT behaves with `maxTrainerDefeats: -1` too.
  - Advancements / `DefeatCountCondition` use the per-trainer defeat count, which keeps growing; conditions written as `== 1` stop matching after the first win (as intended).

## Work plan

**Part 2 – code, state, command** (no screens yet)
1. `challenge/ChallengeCode.kt`: decode / encode TW1 and TWR1, tested against `challenge-vectors.json` (see the notes in `3.0-part1-prompt.md`: CRC32 over the base64url part without `=`, strict integer checks, `disableHtmlEscaping`, TWR1 JSON order `v`, `code`, `allow`).

## Notes from part 2

- Chat input is limited to 256 characters and a TW1 code is longer, so `/challenge start <code>` can't take a real code from chat. Until the Roster screen exists it needs a command block (`execute as @p run challenge start <code>`).
- No other mod in the pack registers `/challenge` (all jars in `mods/` were scanned for the literal).
- `8afaf5f` went up in the same push as `68e8ea5`, so only `68e8ea5` has a CI run.
- Part 3: the `POKEMON_GAINED` filter (`pokemon.getOwnerUUID() == playerId`) is not checked in bytecode for trades and catches; sweep the party right before every validity check so a missed event can't change the result.

## Notes from part 3

Done:

- `/challenge paste` + "Paste challenge code" key (clipboard → payload, max 8192 chars); `/challenge copyreroll`. The client catches `/challenge paste` with `ClientSendMessageEvents.ALLOW_COMMAND`, because a client command on the same root would stop `/challenge status` etc. (Fabric only passes "unknown command" errors on to the server).
- Config `rctLootOnRematch`, `unlimitedRematches`, `challengeRegions`.
- Party check, battle cancel, win / loss, Master Ball / Shiny Berry, shiny feathers, rematch mixins.

Rules added in part 3 (not decided by the owner; interim, can change):

- Until the screens exist, Defeat choices and shiny stat choices are clickable chat lines (`/challenge defeat keep|reroll1|rerollall`, `/challenge shiny <slot> <stat>`).
- Challenge battles are blocked while a defeat choice is pending, while waiting for the Reroll 1 code, and while a shiny reward has no stat picked yet. A Reroll 1 can't be cancelled once picked (Abandon still works).
- A battle only counts if its party check passed for the same team; pasting or rerolling a code during a battle is refused.
- The "blocked" text is shown at most every 10 s per trainer (force-battle-on-sight retries).
- `TrainerMob.wasExhausted()` is left alone: it only slows a beaten trainer's walking speed (`lambda$registerGoals$10`, ×0.25 instead of ×0.75).

Not tested in game yet: every RCT hook is `require = 0`, so a hook that doesn't attach fails silently; RCT is compile-only, so `runClient` can't test it.

## Risks

1. The mixins depend on rctmod 0.19.2-beta bytecode. With `require=0` a different RCT version silently turns features off; a startup check logs a warning.
2. Pokémon from before the mod was installed have no ownership history; they are treated as already owned.
3. The CRC only catches typos; it doesn't stop hand-made codes. Fine for single player.
4. A TWR1 code is about 1,500 characters: raise the text field limit and add a Copy button.
5. Rematches can farm the random loot pools of RCT trainers.
